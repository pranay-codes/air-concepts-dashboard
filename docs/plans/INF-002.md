# INF-002 implementation plan

Approved in conversation on 5 November 2026. Implement inline.

## Prompt contract
Goal: one CloudFormation blueprint with separate non-secret Test and Live
configuration, plus Docker/Caddy hosting configuration. Source: the human-linked
INF-002 Notion task (40b5eb9488648130a4aed9283bc50ca5) and its Infrastructure
Architecture reference (40a5eb94886481408eb6dc4e1647c34c), read this session.
The task-specific AGENTS.md exception waives the local spec-pack gate.

Constraints: Sydney, ARM64 AL2023, Test micro/10 GiB, Live small/20 GiB,
SSM administration, encrypted storage, private S3/OAC, environment-scoped IAM.
No AWS calls, deployments, secret reads, database changes or unrelated changes.
Live configuration is a blueprint, not production readiness or release approval.

## Files and checks
1. Write `infra/scripts/test_infrastructure.py` first. Assert INF-002 sizing,
   forbidden ports, IMDSv2, private S3/OAC, IAM separation, configuration parity,
   immutable images and Compose isolation. Run and observe missing-template failure.
2. Create `infra/cloudformation/infrastructure.json` and
   `infra/params/{test,live}.example.json`. Environment determines safe default
   sizing and parameter paths. Allow explicit size overrides, optional DNS,
   existing ECR and customer-managed SSM KMS keys. Reject invalid combinations.
3. Create `infra/deploy/compose.yaml` and `infra/deploy/Caddyfile`.
   CI-002 owns Java image construction, secret injection and actual release.
   No backend Dockerfile exists yet; document the required image interface.
4. Update `infra/README.md`, add local checks to PR CI and pin validation tools
   in `infra/scripts/requirements-infrastructure.txt`.
5. Run offline unittest, cfn-lint, Compose config validation and git diff checks.
   Link the infrastructure guide from `docs/README.md`.

## Failure modes / review focus
- Selecting Live must never retain Test sizing defaults or Test secret access.
- Existing ECR must not be created twice; preserve tagged rollback images.
- Optional custom frontend hostname requires a matching us-east-1 certificate.
- Bootstrap failure must fail stack creation; EC2 replacement needs review.
- SPA routes must not turn missing assets or access errors into cached HTML.

## Definition of Done and evidence boundary
Local assertions and cfn-lint pass for the shared blueprint; Compose validates;
configuration and manual deployment/rebuild procedures are documented.
Cross-tool Claude review, remote CI, AWS validate-template/change-set review,
Test acceptance, ARM64 runtime/TLS and capacity proof remain explicit external
gates. Never claim INF-002 fully provisioned from local checks.
