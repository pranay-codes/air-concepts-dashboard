## Documentation research (not a confirmed spike)

- [GL Xero quotes and contacts](../spikes/gl-xero-quotes-contacts.md), [GL Xero invoice writes](../spikes/gl-xero-invoice-write.md), and [GL vWork](../spikes/gl-vwork-api.md) record documented facts, unverified behaviour and safe fallbacks. Xero's current scope documentation places Quotes under `accounting.invoices.read`; the general paging documentation does not list Quotes, so do not assume invoice paging applies.
- [vWork API v5 Jobs](https://apidocs.vworkapp.com/v5-jobs) documents the stable Jobs API, gzip response support, and several HTTP errors. Its documentation describes API keys and ISO 8601 timestamps. The actual account and integration behaviour have not been tested.
- [vWork job templates and the API](https://help.vworkapp.com/hc/en-us/articles/360036287351-Job-templates-and-the-API) distinguishes the standard Jobs API, where `template_name` is free text, from the Templated Jobs API, which creates jobs from saved templates. This does not establish that job reads and search results carry a stable template ID suitable for entity isolation (plan decision D5).
- [Assign a job to a worker](https://help.vworkapp.com/hc/en-us/articles/203694660-Can-I-assign-a-job-to-a-worker-via-the-API) documents v5 XML job creation and update examples with `worker_id` and `planned_start_at`, including key authentication in a query parameter. Any implementation must prevent keys in URLs from entering logs or error messages.
- [vWork job statuses](https://apidocs.vworkapp.com/v5-jobs/jobs-and-status) documents eleven status values and constraints on completed jobs; [Templated Jobs](https://apidocs.vworkapp.com/v5-templated-jobs) documents creation from a template name or ID. Neither source on its own verifies D5 read-back or account-specific configuration.
- [Templated job creation](https://apidocs.vworkapp.com/v5-templated-jobs/templated-job-creation) documents `POST /api/v5/jobs/clone.xml`, a query API key, gzip and XML; the example response contains `template_name` but does not establish stable template-ID read-back. Because templates inherit configuration and may include invoice details, GL-26 needs explicit proof that the chosen template cannot introduce prices before enabling job creation.
- [Xero invoices](https://developer.xero.com/documentation/api/accounting/invoices) documents invoice read/write and attachments up to 25 MB, and [Xero idempotency](https://developer.xero.com/documentation/guides/idempotent-requests/idempotency/) describes the `Idempotency-Key` header. Demo-account behaviour, scope access and endpoint-specific replay are not verified.
- Search, completion fields, report retrieval, template identity, signing, idempotency and the remaining provider behaviour required by GL-T02–T04 remain unconfirmed. The above references alone do not justify inventing fixtures or claiming provider compatibility.
