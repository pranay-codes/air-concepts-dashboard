# UC4 Excel template map — "ACSL Cashflow Forecast Template - Cleaned.xlsx"

Source file: `docs/ACSL Cashflow Forecast Template - Cleaned.xlsx` (39,847 bytes, inspected
10 November 2026 by reading the OOXML parts directly). This document is the contract between
the backend `WorkbookValidator` / `WorkbookPopulator` and the client's standard workbook. Any
change to the workbook layout is a new template version and needs a new section here.

Template version: **v1** (no marker cell exists; the validator identifies v1 by the structural
fingerprint in section 6).

## 1. Workbook facts

| Fact | Value |
| --- | --- |
| Worksheets, in order | `Assumptions`, `Forecast 2026-2027`, `Xero_Debtors`, `Xero_Creditors`, `Staffing` |
| Defined names | none |
| Macros, external links, data validation, conditional formatting, sheet protection | none |
| Hard-coded entity name | `Assumptions!A1`, `Forecast!A1`, `Staffing!A1` all read "AIR CONCEPTS SERVICE LTD …" |
| Sheet name with years | The forecast sheet is named `Forecast 2026-2027`; the year range is cosmetic (`A3` recomputes it) |
| Document capacity | 200 rows per Xero sheet (`A5:E204`); every Forecast formula references `$5:$204` fixed |
| Named-contact rows | 15 debtor contacts (`Forecast!A8:A22`), 20 creditor contacts (`Forecast!A29:A48`); remainder flows to "Other … (not listed above)" |
| Manual rows | 1 "Other receipts (manual)" row (`Forecast!B25:M25`); 10 "Direct debits & other payments" rows (`Forecast!A56:M65`) |
| Staffing capacity | 6 staff table rows (`Staffing!10:15`), 7 monthly grid rows (`Staffing!23:29`) |
| Staffing month axis | `Staffing!D19:BN19` holds 63 month dates (1 Apr 2022 to 1 Jun 2027); `Forecast!B53:M53` looks months up here with `INDEX/MATCH` |

The sample contains personal data (four staff names and one hourly rate on `Staffing`). The
committed test fixture must be scrubbed before it enters the repository (gate G5).

| Rows | Content | Backend action |
| --- | --- | --- |

| A2 | Legend text | Preserve |
| 3 | Month header formulas | Preserve |
| 5 | `Beginning Balance`: `B5 = Assumptions!$B$5`, `C5 = B68` … | Preserve |

| 8–22 | Per-contact receipt rows. `A` = contact name (manual, must match Xero exactly); `B:M` = `SUMIFS(Xero_Debtors!$E, $A, $G, month)` | Write the top 15 debtor contacts by total forecast amount into `A8:A22` (blank the rest); preserve formulas |
| 23 | "Other debtors (not listed above)" catch-all formula | Preserve |

| 66 | `Total Direct Debits = SUM(B56:B65)` | Preserve |

Rename the sheet to `Forecast <startYear>-<endYear>` after populating. The validator accepts
any sheet whose name starts with `Forecast` and whose row 3/5/26/67/68 formulas match the
fingerprint.

## 4. Sheets `Xero_Debtors` and `Xero_Creditors` (A1:G204, identical layout)

| Cell / range | Template | Backend action |
| --- | --- | --- |
| A1 | "XERO DEBTORS - AGED RECEIVABLES DETAIL" / "XERO CREDITORS - AGED PAYABLES DETAIL" | Preserve |
| A2 | Paste instructions | Preserve |
| A3, F3, G3 | "Xero-derived (paste)", "Manual (optional)", "Formula" | Validate |
| A4:G4 | `Contact`, `Invoice No`, `Invoice Date`, `Due Date`, `Amount Due`, `Override Pay Date`, `Forecast Month` | Validate exact text |
| A5:E204 | Data area (empty in template) | Write one row per **forecast contribution** (see below), clear any leftover rows |
| F5:F204 | Override pay date (manual) | **Always write** the bucket date the calculator used (first day of the bucket month) so the sheet's month equals the dashboard's month |
| G5:G204 | `=IF(OR(D="",E=""),"",MAX(DATE(YEAR(IF(F<>"",F,D+delay)),MONTH(…),1),Assumptions!$B$4))` | Preserve |

Row content per contribution:

| Column | Value |
| --- | --- |
| A Contact | `contact_name` exactly as stored from Xero |
| B Invoice No | `number`; for split lines append ` (k/n)`; if `number` is null use `xero_document_id` first 8 chars |
| C Invoice Date | `issue_date` (date cell) |
| D Due Date | `due_date`, or `issue_date` when null (the dashboard flags `MISSING_DUE_DATE`) |
| E Amount Due | `amount_due`, or the split line `amount` |
| F Override Pay Date | first day of the calculator's bucket month (`OverduePolicy` already applied) |

Excluded documents are **not** written; the dashboard holds the exclusion list. Contributions
dated after month 12 are written with their real bucket date so the sheet's `SUMIFS` ignores
them, which matches the calculator's `beyondWindow` handling.

Capacity: more than 200 contributions on either sheet → `FORECAST_TEMPLATE_CAPACITY` with the
counts; no file is returned. Raising the cap needs template v2 (widen every `$5:$204`
reference to `$5:$1004` in `Forecast` and both Xero sheets).

## 5. Sheet `Staffing` (A1:BN47)

Two regions are relevant. The dashboard model is one `monthly_cost` per staffing line, so the
backend writes **values** into the monthly grid and does not rely on the template's
hourly × 40 × 52 formulas, whose weeks-per-month weighting would not reconcile with the
dashboard.

Staff table (rows 5–16):

| Range | Template | Backend action |
| --- | --- | --- |
| A1 | "AIR CONCEPTS SERVICE LTD" | Write entity name upper-cased |
| A5:I7 | Headers `First Name`, `Surname`, `Role`, `Hourly Rate`, `Annual Cost Gross`, `Kiwisaver` (F6 = 3 %), `Annual Cost Gross`, `Monthly Cost Gross`, `Notes` | Validate `A5`, `B5`, `C5`, `H5` text |
| A9 | Group label "SERVICE" | Write entity name |
| A10:I15 | 6 staff rows with formulas in E, F, G, H | Write `label` into `C`, blank `A`, `B`, `D`, `E`, `F`, `G`; write `monthly_cost` as a **value** in `H`; write "Dashboard staffing line" in `I` |
| 16 | Totals `E16:H16 = SUM(…10:15)` | Preserve |

Monthly grid (rows 19–30):

| Range | Template | Backend action |
| --- | --- | --- |
| D19:BN19 | 63 month dates, 1 Apr 2022 to 1 Jun 2027 | Write the 12 forecast months into `D19:O19` as dates; **clear** `P19:BN19` |
| A20, D20:BN20 | "Weeks" and 4/5 per month | Write the number of Mondays in each forecast month into `D20:O20` (informational); clear the rest |
| A22 | "SERVICE" | Write entity name |
| A23:C29 | Staff identity formulas/values | Write `label` into `C`; blank `A`, `B` |
| D23:O29 | `=$G$10/52*D20` style formulas | Write `monthly_cost` as a **value** for each active line and month; blank months where the line is inactive (`start_month`/`end_month`); clear `P23:BN29` |
| 30 | `Total ACSL`: `D30 = SUM(D23:D29)` … `BN30` | Preserve (this is what `Forecast!53` reads) |
| 33 | ACC levy row (`= row 30 × 1.5 %`) | Preserve; not referenced by `Forecast` |

Capacity: 7 grid rows (23–29) and 6 table rows (10–15). With more than 6 lines the backend
writes the 5 largest individually and aggregates the rest into row 15 / row 28 as
"Other staff (n lines)". Totals still reconcile; the aggregation is listed in the export
warnings so it is never silent.

Known template defects to tolerate, not reproduce: `Staffing!D25:L25` reference row 21 instead
of row 20, and `AH24:BN24` hold literal numbers. Because the backend overwrites `D23:O29` with
values these cells never affect output.

## 6. Validation fingerprint for template v1

The validator rejects the upload unless all of the following hold:

1. Exactly these sheets exist, in any order: `Assumptions`, one sheet starting `Forecast`, `Xero_Debtors`, `Xero_Creditors`, `Staffing`.
2. `Assumptions!A3:C3` = `Assumption`, `Value`, `Note`; `A4:A7` labels as in §2.
3. `Xero_Debtors!A4:G4` and `Xero_Creditors!A4:G4` headers as in §4; `G5` and `G204` are formulas referencing `Assumptions!$B$4`.
4. `Forecast!B3` formula is `Assumptions!$B$4`; `B5` is `Assumptions!$B$5`; `B26` is `SUM(B8:B25)`; `B67` is `B50+B53+B66`; `B68` is `B5+B26-B67`; `B53` contains `Staffing!$D$30:$BN$30`.
5. `Staffing!A5:C5` = `First Name`, `Surname`, `Role`; `H5` = `Monthly`; `D30` formula is `SUM(D23:D29)`.
6. No VBA part, no external link part, no sheet protection.
7. Formula functions used anywhere are within the supported set: `IF`, `OR`, `SUM`, `SUMIFS`, `MAX`, `DATE`, `YEAR`, `MONTH`, `EDATE`, `INDEX`, `MATCH`, string concatenation. Any other function → `FORECAST_FORMULA_UNSUPPORTED` naming the cell.

Every failed check becomes one entry in the 422 `problems[]` list with sheet, cell and
expected value.

## 7. Reconciliation cells

After `setForceFormulaRecalculation(true)` and a POI `evaluateAllFormulaCells` pass, compare:

| Workbook range | Calculator value |
| --- | --- |
| `Forecast!B26:M26` | `MonthRow.receipts` |
| `Forecast!B67:M67` | `MonthRow.payments` |
| `Forecast!B68:M68` | `MonthRow.closing` |
| `Forecast!B5` | `openingBalance` |

Any absolute difference above 0.005 sets `reconciled = false` and adds a warning naming the
month and both values. All functions in §6.7 are implemented by POI's evaluator, so a
`NotImplementedException` indicates a template change and is reported as
`FORECAST_FORMULA_UNSUPPORTED`.

- Remove the pre-filled staff names and the hourly rate from the standard template.
