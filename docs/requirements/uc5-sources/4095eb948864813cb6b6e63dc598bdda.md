# 🧾 Use Case 5 — Connect Xero Organisations and View Sales Invoices & Supplier Bills (Green Lane)

Source: https://app.notion.com/p/4095eb948864813cb6b6e63dc598bdda

Fetched: 6 November 2026. Point-in-time reference; canonical use case governs conflicts.


<b>Status:</b> Updated functional specification — requirements aligned with confirmed Green Lane decisions through <date start="2026-11-06" />. This page defines the intended scope; it does <b>not</b> indicate that Xero integrations, invoice retrieval, or attachment functionality have been implemented or verified.

<b>Business outcome:</b> Authorised Air Concepts staff can sign in, select a configured business entity, and view sales invoices and supplier bills from its corresponding Xero organisation in one responsive dashboard. The Director can connect and maintain a <b>dynamic number of Xero organisations</b> through the application. Xero is the financial system of record; the dashboard manages only its own users, entity mappings, and sales-invoice staff assignments.

<b>Organisation scope:</b> Commercial, Services, and HotAS are initial examples only, <b>not</b> a fixed list or application-imposed maximum. The Director can add further entities and link authorised Xero organisations without code changes, subject to actual Xero access, connection limits and API terms. The Green Lane permissions model makes all configured entities accessible to active dashboard users, while protecting supplier bills and privileged actions by role.

## Client demonstration — core flow

1. An existing, active user signs in with an emailed, single-use six-digit code.
2. The Director opens <b>Settings → Entities</b>, adds a business entity, authorises Xero, and selects the correct Xero organisation. Repeat for additional organisations as required.
3. An authorised user selects an entity using the application-level selector and opens <b>Invoices</b>.
4. The user selects <b>Sales Invoices</b> or, if permitted, <b>Supplier Bills</b>; searches, filters, sorts and opens read-only details.
5. The user previews/downloads available invoice or bill attachments. The Director or Financial Admin may assign or reassign <b>sales invoices only</b> to active dashboard users.
6. A user changes entities, and the page reloads records from the newly selected Xero organisation without mixing entity data.

<b>Start:</b> An active, registered dashboard user opens the login page.

<b>End:</b> An authorised user views the selected entity's Xero invoices/bills and available documents; financial values are not modified in Xero.

## Roles and access

| Capability | Director | Financial Admin | Standard User |
| --- | --- | --- | --- |
| View sales invoices and their attachments | Yes | Yes | Yes |
| Assign/reassign sales invoice owners | Yes | Yes | No |
| View supplier bills and their attachments | Yes | Yes | No |
| Assign supplier bill owners | No — out of scope | No — out of scope | No |
| Create/connect/reconnect/remap Xero entities | Yes | No | No |
| Add users, assign roles, deactivate users | Yes | No | No |

- <b>Entity access:</b> In Green Lane, active dashboard users can view sales invoices for every configured entity, including newly added entities. Supplier bill visibility remains restricted to Director and Financial Admin. Backend checks apply to each entity- and invoice-specific request.
- <b>Xero authorising user:</b> The person consenting to Xero must have the necessary rights in that Xero organisation. Being a dashboard Director does not automatically confer Xero rights.
- <b>Inactive user:</b> Cannot sign in or continue accessing protected backend functions. Existing sales invoice assignments stay identifiable with an Inactive indicator; no automatic reassignment or deletion.

## Standard workflow and business rules

### A. Sign-in and user administration

1. The Director registers users in <b>Settings → Users</b> and assigns Director, Financial Admin or Standard User roles. Public self-registration is not provided.
2. A registered active user enters their email and receives a one-time <b>six-digit numeric</b> passcode; it expires in <b>10 minutes</b>, can be used once only, and both requests and verification are rate-limited. No separate dashboard password or Microsoft 365 login is required.
3. Backend authorisation verifies both role and active status for protected operations, including existing sessions after deactivation.
4. Only the Director deactivates users. Deactivation preserves historical sales-invoice ownership; only active users are available for new assignments.

### B. Connecting and selecting Xero organisations

1. The Director opens <b>Settings → Entities</b> and adds an entity using a meaningful display name; the UI must not hard-code three entity names or fixed tabs.
2. The Director selects <b>Connect Xero</b>. A standard OAuth 2.0 authorisation-code flow is completed by a properly authorised Xero user.
3. The backend discovers the authorised Xero organisations and the Director confirms which organisation is mapped to the selected dashboard entity. Record the immutable tenant ID and its association; reject duplicate/conflicting mappings.
4. Settings displays each entity, connected Xero organisation, and <b>Connected / Not connected / Needs reconnection</b> status. Only a Director can initiate authorisation, reconnection or remapping.
5. One configured Xero OAuth application may grant access to multiple organisations. Tokens remain server-side and may cover more than one tenant; do <b>not</b> assume one token pair per organisation. Refresh/rotate tokens safely and use the correct tenant ID for every scoped request.
6. The application-wide selector lists all accessible configured entities; remember the user's most recent selection where possible, but always validate access and mapping server-side. If there is no connected entity, show setup/reconnection guidance rather than a broken invoice list.

### C. Invoices page — two tabs

- A single <b>Invoices</b> page has <b>Sales Invoices (ACCREC)</b> and <b>Supplier Bills (ACCPAY)</b> tabs. Standard Users cannot see or call the Supplier Bills tab, APIs or attachment endpoints.
- Show one selected entity at a time; <b>no combined cross-entity invoice view</b> in this release. Changing entity reloads the chosen tab using that entity's tenant mapping.
- For <b>both</b> tabs, the default is <b>all available Xero statuses</b> and <b>all dates</b>, sorted by <b>invoice date newest first</b>. Include invoices/bills entered directly into Xero.
- Search by invoice/bill number, reference, and customer/supplier name. Filters include original Xero status and an <b>Overdue</b> view.
- Date filtering uses either <b>Invoice Date</b> or <b>Due Date</b> with <b>This Month, Last 3 Months, This Year, Custom Range</b>. Custom range has start/end dates. Search, status and date filters must work together.
- Allow sorting by invoice date, due date, amount, status and contact. Use stable, full-result pagination: do not search/filter only the visible page or truncate older matching invoices to the first Xero API page.
- Display the original Xero status unchanged. <b>Overdue</b> is a separate calculated indicator when the due date has passed and a positive balance remains on an invoice/bill eligible for payment; paid, draft, deleted and voided records must not be flagged overdue. Partially paid records use the remaining outstanding balance.
- Retrieve current Xero records when an invoice tab opens or entity changes, with manual <b>Refresh</b>. No scheduled background invoice synchronisation or separate last-successful-invoice cache is required for Green Lane.
- On retrieval, connection or rate-limit errors show a clear message and <b>Retry</b> or Director-only reconnection guidance. Never present failed/stale data as current.

### D. List and detail views

- <b>Sales list:</b> Number, customer, reference, invoice date, due date, total, amount due, Xero status, overdue indicator and Assigned to.
- <b>Supplier bills list:</b> Number, supplier, reference, bill/invoice date, due date, total, amount due, Xero status and overdue indicator. <b>No Assigned to field</b> and no supplier bill ownership functionality.
- <b>Both details:</b> In-dashboard, read-only view showing contact, number, reference, dates, original Xero status, line items with description/quantity/unit price, subtotal, GST/tax, total, available payment information and remaining balance.
- <b>Attachments:</b> For both sales invoices and supplier bills, an authorised user may see available attachments, preview supported PDF/image files within the dashboard, and download the original files. Where preview is unsupported, offer download. All metadata/file retrieval is authorised via the backend against the exact entity, tenant, document and role. No upload, edit or delete.
- <b>Sales invoice assignment:</b> Director and Financial Admin may assign/reassign an <b>active</b> dashboard user from the list or detail view. Save assignment in the dashboard against entity + Xero invoice ID; do not update Xero. Unassigned rows show <b>-</b>. Assignments survive refresh; inactive assignees remain visible with an Inactive label until reassigned.

### E. UX, accessibility and application boundaries

- Follow the supplied wireframe as the visual reference when available. Use a <b>light-only theme</b>, consistent entity selector, clear tab labels, mobile-friendly invoice cards and responsive desktop tables.
- Provide loading, empty, disconnected, failed, no-attachment and no-access states. Label dates, currency, balances, invoice type, status and selected entity clearly.
- Use the established React frontend, Spring Boot backend and Supabase Auth/Postgres architecture. The backend alone handles Xero API calls, OAuth client secrets and token lifecycle.
- Xero remains authoritative for all accounting fields and document status. The dashboard does not become a separate editable Xero ledger.

## Acceptance criteria — executable scenarios for spec pack

1. <b>Login:</b> A registered active user can sign in with a six-digit emailed code before ten minutes; expired, replayed or excessive attempts fail, and unauthorised signup is unavailable.
2. <b>Deactivation:</b> A deactivated user cannot use a previously issued code, sign in, or call protected APIs with an existing session; their historical invoice assignments remain visible.
3. <b>Director-only setup:</b> Director can add and map a business entity to an authorised Xero organisation, see its status and reconnect; Financial Admin and Standard User cannot invoke those backend operations.
4. <b>Dynamic growth:</b> With zero, one, three and more than three configured entities, the selector and mappings behave correctly; adding a new eligible organisation requires no code or redeployment, within applicable Xero provider limits.
5. <b>Tenant isolation:</b> Each request for invoices, bills, assignments and attachments uses the selected entity's validated tenant; no record from a different organisation leaks across entity changes.
6. <b>Role matrix:</b> All active roles can view permitted sales invoices and sales attachments. Only Director and Financial Admin can view supplier bills and their attachments; Standard Users are denied via direct API/attachment URLs as well as the UI.
7. <b>Two tabs:</b> Invoices contains Sales Invoices and Supplier Bills; switching entity or tab loads the correct invoice type from the correct organisation.
8. <b>All statuses:</b> Both tabs initially display all available statuses and dates; directly created Xero invoices/bills are included and no list silently truncates at the first page.
9. <b>Filtering:</b> Full-result search, Xero-status/Overdue filters and date filters work together with presets, custom ranges, correct entity and tab scoping.
10. <b>Sorting:</b> Default is invoice date newest first for each tab; available column sorting remains consistent through pagination.
11. <b>Overdue:</b> Past-due, partly paid eligible invoices show Overdue using outstanding amount; paid/voided/deleted/draft invoices do not, and Xero's original status remains visible.
12. <b>Sales list/details:</b> Fields, lines, taxes, payments and balance match the selected organisation's Xero sales invoice; accounting data is not edited in the dashboard.
13. <b>Supplier list/details:</b> Fields, lines, taxes, payments and balance match the selected organisation's Xero supplier bill; there are no assignment, approval, payment or editing controls.
14. <b>Attachments:</b> Available attachments for both types can be listed, PDFs/images previewed, and originals downloaded by authorised roles; missing/unpreviewable files have safe UX fallbacks.
15. <b>Sales ownership:</b> Director/Financial Admin can assign active users from list and detail, with persistence after refresh; Standard Users cannot modify assignment. Unassigned is a dash.
16. <b>Inactive assignee:</b> Existing assignments remain visibly associated with inactive staff, who cannot be selected for new assignments.
17. <b>Refresh/errors:</b> Tab open/entity changes/manual Refresh retrieve current records; Xero failures show Retry/reconnection information and do not present previously retrieved data as current.
18. <b>Responsive:</b> Desktop/tablet/mobile layouts match approved wireframe direction, remain usable and distinguish type, entity, balance and status; Standard User never sees Supplier Bills navigation.
19. <b>No financial writes:</b> Attempts to create, change, approve, pay, send or remove Xero accounting records through these screens are not supported.
20. <b>Security:</b> Browser receives neither OAuth tokens nor secrets; sensitive operations, file access and tenant selection are server-authorised.

## Out of scope for this Green Lane case

- Creating, editing, sending or approving Xero sales invoices or supplier bills; paying supplier bills; changing Xero financial data or statuses.
- Assigning supplier bills to staff; automatic sales assignment rules; sending reminders, collections or follow-up automation.
- Uploading/editing/deleting invoice or bill attachments.
- Forecasting, split-payment schedules, progress claims, vWork, bank transaction browsing or payroll workflows.
- A combined cross-entity invoice view, consolidated financial reporting or intercompany elimination.
- Scheduled background invoice synchronisation, separate cached invoice ledger, bulk CSV/PDF exports or n8n orchestration.
- Reactivating inactive dashboard users (separate future use case).
