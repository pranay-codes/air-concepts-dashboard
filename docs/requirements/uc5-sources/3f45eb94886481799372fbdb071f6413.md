## Project

## Business and technical context

The business brief records the problems, evidence, stakeholders and business requirements. The product specification and solution design hold technical choices and validation work; detailed functional requirements live in the use-case pages.

<b>Current technical hosting decision (3 November 2026):</b> EC2 t4g.small (2 GiB ARM64, Amazon Linux 2023, Docker/JDK 25) for each independently secured Test and Live backend; Supabase for database/Auth; private S3/CloudFront for frontend; GitHub Actions → AWS OIDC → ECR → Systems Manager Run Command for deployments. No inbound SSH; independent Supabase projects and IAM/secret boundaries. Cost, 4 GiB fallback, backups and NZ Privacy Act/IPPs data-flow assessment remain validation/approval items. See <mention url="https://app.notion.com/p/40a5eb94886481408eb6dc4e1647c34c">Infrastructure Architecture</mention> and <mention url="https://app.notion.com/p/40b5eb9488648121807eee3c8c6b2c58">Implementation Plan — Agentic Development & Delivery (Living)</mention>.

## Delivery sequence

Recorded agreement: HotAS forecasting → Services and Commercial forecasting → bill uploads into Xero → financial admin application. Detailed scope and acceptance remain subject to the questions in each use case.

The overall requirements include work delivered outside the dashboard. Phase 3 supplier bill capture is a separate automation into Xero, with human review and approval of draft bills. It can be delivered before the dashboard; its canonical requirements sit within Use Case 3.
